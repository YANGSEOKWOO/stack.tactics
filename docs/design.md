# stack.tactics — 게임 설계 / 밸런스 문서

> 개발 스택을 조립해 버그를 막아내는 PvE 오토배틀러.
> 이 문서는 프로토타입과 함께 계속 고쳐나가는 **살아있는 설계서**다.
> 아래 수치는 전부 "플레이테스트 시작점"이며 확정값이 아니다.

---

## 1. 코어 메커니즘 (확정)

두 개의 축으로 성장한다.

- **세로축 — 별업(star-up):** 같은 기물 3개 → 1개의 ★★ (자동). 같은 길을 깊게 판다.
- **가로축 — 합성/배포(fusion):** 서로 다른 카테고리 기물을 보드에 모으고 `deploy`로 합성 유닛 생성 (수동). 폭을 넓힌다.

두 축은 **자원 경쟁** 관계다. 합성에 쓰면 그 재료는 별업에 못 쓰고, 보드 칸 2개를 잃는 대신 강한 1유닛을 얻는다. 이 트레이드오프가 게임의 의사결정 핵심.

---

## 2. 밸런스 철학 — 조절 레버

밸런스를 "숫자 하나"가 아니라 아래 레버들의 균형으로 본다.

1. **유닛 수 vs 유닛 강함** — 오토배틀러에서 머릿수는 강력하다. 합성 유닛(머릿수↓, 단일 파워↑)이 항상 정답이 되면 안 된다. 광역 공격 적/단일 공격 적을 섞어서 "뭉치는 빌드 / 펼치는 빌드" 둘 다 답이 되게 한다.
2. **경제 vs 전력** — 골드를 아껴 이자를 굴릴지(장기), 당장 리롤해서 보드를 강화할지(단기)의 긴장.
3. **별업 vs 합성** — 위 1번 트레이드오프. 합성 유닛에 **시너지 버프**까지 얹으면 가로축 매력이 커지므로, 별업 보상과 균형을 맞춘다.
4. **유연성 비용** — 여러 카테고리에 손대면 시너지/합성 옵션은 늘지만 별업과 경제가 흔들린다.

> 황금률: 어떤 단일 전략도 60% 이상 승률을 내면 안 된다. "조합 다양성"이 보상받아야 한다.

---

## 3. 경제 모델 (제안 — 프로토타입엔 일부만 반영)

| 항목 | 값 | 비고 |
|---|---|---|
| 시작 골드 / 체력 | 8 / 100 | |
| 라운드 기본 수입 | +5 | |
| 이자 | 보유 골드 10당 +1, 최대 +5 | 50골드 모으면 최대 |
| 연승/연패 보너스 | 2/3/4+연속 → +1/+2/+3 | 연패도 보너스(일부러 지고 경제 굴리기 허용) |
| 리롤 | 2골드 | |
| 판매 환급 | 기물: 원가×성급 / 합성: 3골드 | |
| 경험치 구매 | 4골드 → 4 XP | 레벨업으로 보드 칸·상점 확률 상승 |

**레벨 = 보드 배치 가능 수.** 보드는 TFT식 4×7 벌집(28칸)이고, 레벨 4에서 시작해 최대 10기까지 올린다.

**전열(위치) 전략:** 버그는 살아있는 유닛이 있는 가장 앞 행부터 때린다. 탱커(SG·VPC·Java·K8s)를 앞줄에, 캐리를 뒷줄에 두는 배치가 곧 전략이다. (구 "카테고리 방어 계층" Infra→FE→BE→DB 규칙을 대체.)

---

## 4. 기물 등급(코스트)과 상점 확률

코스트는 곧 희귀도. 레벨이 오를수록 고코스트 등장 확률이 올라간다 (TFT 방식).

| 레벨 | 1코 | 2코 | 3코 | 4코 | 5코 |
|---|---|---|---|---|---|
| 2 | 70% | 30% | 0 | 0 | 0 |
| 4 | 45% | 35% | 18% | 2% | 0 |
| 6 | 25% | 35% | 28% | 10% | 2% |
| 8 | 18% | 25% | 30% | 22% | 5% |

각 코스트의 기물 총 보유 수(풀)도 제한해서, 같은 걸 많이 사면 남이 못 사게 하는 경쟁 요소를 둘 수 있다(멀티 도입 시).

## 6. 시너지(트레잇) 버프 — 가로축에 깊이 추가

현재 합성은 "유닛 생성"만 하고 버프가 없다. 카테고리별 보유 수에 따라 전체 버프를 주면 "세트 모으기"의 맛이 생긴다.

| 트레잇 | 2 | 4 | 6 | 효과 |
|---|---|---|---|---|
| Frontend | ✓ | ✓ | ✓ | 공격 속도 +15/30/50% |
| Backend | ✓ | ✓ | | 최대 HP +20/40% |
| Infra | ✓ | ✓ | | 받는 피해 -15/30% (보호막) |
| Database | ✓ | ✓ | | 초당 체력 회복 |
| Security | ✓ | ✓ | | 라운드 시작 시 전체 보호막 |

> 합성 유닛은 자기 카테고리 카운트에 **2 이상**으로 기여하게 해서, 합성=시너지 가속이 되도록 설계 가능.

## 7. 합성 트리 (컴포넌트 → 시스템 → 플랫폼)

시그니처가 될 "테크 트리" 진행. 단계가 올라갈수록 강하지만 더 많은 칸/자원을 먹는다.

```
[컴포넌트]                 [시스템]              [플랫폼/엔드게임]
HTML + CSS + JS      →     Frontend  ┐
Java + Node + Go     →     Backend   ├→  Web App (FE+BE)      ┐
Postgres+Redis+Mongo →     DataLayer ┘                        ├→ Production System
VPC + LB + SG        →     Infra ───────→ Cloud Native (Infra+BE) ┘   (FullStack + Infra)
```

- 현재 프로토타입 구현: `Frontend`, `Infra` (1단계만)
- 다음 단계: 시스템끼리 합쳐 `Web App`, `Full Stack` 등 2단계 합성

---

## 8. 적 / 라운드 설계

- 일반 라운드: 버그 웨이브 (Bug, NPE, 404, RaceCond, MemLeak, Timeout). 스테이지에 따라 수/체력/공격 증가.
- **보스 라운드 (5스테이지마다):**
  - `Outage` — 광역 딜, 펼치는 빌드 강요
  - `Data Breach` — 단일 고딜, 탱커 요구
  - `DDoS` — 다수 소환, 머릿수 싸움
- 보상: 보스 처치 시 골드 + 코스트 높은 기물 선택권(증강체 느낌).

---

## 9. 플레이버 이벤트 (선택)

라운드 사이 랜덤 이벤트로 개발 유머를 살린다.
- **Merge Conflict** — 무작위 두 기물 위치 교체
- **Tech Debt** — 보드 전체 일시 디버프, 다음 라운드 골드 보너스
- **Hotfix** — 체력 회복
- **Scaling Event** — 이번 라운드 보드 칸 +1

## 10. 정해야 할 것들 (열린 질문)

1. **합성 유닛도 별업 되나?** → ✅ **구현됨.** 같은 합성 유닛 3개 → ★★ (재료 9개 필요한 엔드게임 플렉스).
2. **시너지 버프를 넣을지** → ✅ **구현됨.** Frontend/Backend/Database/Infra 4종 팀 단위 버프. 합성 유닛은 카테고리 카운트에 2 기여.
3. **레벨/경제 시스템을 슬라이스에 언제 넣을지** → ✅ 경험치·레벨(배치 4→10기, 헥스 보드)·이자·연승연패 반영됨.
4. **멀티플레이 여부** — PvE로 재미 검증 후 결정. 넷코드는 별도 큰 과제.
5. **밸런스 수치 튜닝 방식** — 모든 수치를 이 문서 + `DEFS`/`RECIPES`/`ODDS`/`TRAIT_DEFS` 한 곳에서 관리.
